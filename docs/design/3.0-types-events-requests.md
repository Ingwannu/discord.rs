## 1. 타입 ID (3단계)

구현은 `src/model/id.rs`, 마커는 `src/model/id/marker.rs`. `model`과 크레이트 루트에서 다시 내보낸다.

```rust
#[repr(transparent)]
pub struct Id<M: IdMarker> {
    value: NonZeroU64,
    marker: PhantomData<fn() -> M>,
}

pub type GuildId = Id<marker::Guild>;
pub type ChannelId = Id<marker::Channel>;
pub type GenericId = Id<marker::Generic>;

pub const fn try_new(value: u64) -> Result<Self, InvalidId>;
pub const fn from_nonzero(value: NonZeroU64) -> Self;
pub const fn get(self) -> u64;
pub const fn into_nonzero(self) -> NonZeroU64;
pub const fn timestamp(self) -> u64; // Unix milliseconds
pub const fn erase(self) -> GenericId;
pub const fn cast<N: IdMarker>(self) -> Id<N>;
```

- `IdMarker`는 봉인(sealed)한다. Copy/Clone/Eq/Ord/Hash/Debug/Display는 마커 트레이트를 요구하지
  않게 직접 구현하고, 숫자 값만으로 비교·해시한다.
- 생성: `TryFrom<u64>`, `FromStr`, `TryFrom<&str>`는 실패 가능. `From<NonZeroU64>`만 무실패.
  **`From<u64>`, 패닉하는 `new(u64)`, `Default`, 마커 간 암시적 변환은 두지 않는다.**
- `.cast()`는 "같은 ID라는 단언"일 뿐 존재나 종류를 검증하지 않는다고 문서에 명시한다.
- 직렬화: 십진 문자열(JSON 맵 키 포함). 역직렬화: 십진 문자열 또는 부호 없는 정수. 0, 음수,
  실수, 오버플로, 공백, 부호, 숫자 외 문자는 거부. 앞의 0은 허용하되 정규화한다.
- `Display`는 정규 십진수. `as_str()`처럼 문자열을 저장하거나 누출하는 API는 두지 않는다.

마커: Guild, Channel, User, Role, Message / Application, Command, CommandVersion, Interaction,
Webhook / Emoji, Attachment, Sticker, StickerPack, SoundboardSound / ScheduledEvent,
StageInstance, Integration, AuditLogEntry, AutoModerationRule, ForumTag / Sku, Entitlement,
Subscription, Promotion, RoleSubscriptionListing / Lobby, ActivityLaunch / Team, OnboardingPrompt,
OnboardingOption / Generic. `MemberId`, `PresenceId`, `ThreadId`는 만들지 않는다(멤버·프레즌스는
(GuildId, UserId), 스레드는 ChannelId).

`Snowflake = GenericId`를 deprecated 별칭으로 하나만 남긴다. 느슨한 문자열 생성은 없애고,
정규 엔드포인트 시그니처에는 쓰지 않는다.

엔드포인트는 구체 ID를 값으로 받는다(`impl Into<GuildId>` 금지: 진단이 명확하고 단형화가 줄며
검증이 애플리케이션 경계에서 일어난다).

```rust
pub async fn get_guild(&self, guild_id: GuildId) -> Result<Guild, DiscordError>;
pub trait DiscordModel { type Marker: IdMarker; fn id(&self) -> Id<Self::Marker>; }
```

`manager.rs`의 매니저 트레이트는 `gateway` 기능에 따라 동기/비동기가 바뀌는데, 이 차이를 없앤다.
캐시 키는 `(GuildId, UserId)`, `(ChannelId, MessageId)`, `(GuildId, RoleId)` 같은 구체 튜플.

### Default

필수 ID가 있는 저장 모델에서 `Default`를 제거한다. 센티널 ID를 만들거나 필수 와이어 ID를
`Option`으로 바꾸지 않는다. 빈 쿼리·패치·컬렉션·진짜 선택적 부분 객체는 Default 유지. 테스트 픽스처
생성자는 운영 API 밖에 둔다. 저장된 `ApplicationCommand`와 등록용 데이터(`CommandDefinition`/
`CreateCommand`)를 분리한다. `RestClient`의 미설정 application id는 공개적으로
`Option<ApplicationId>` (내부 원자값 0 센티널은 허용).

## 2. 열린 판별값 (3단계)

비공개 선언 매크로로 투명한 숫자 newtype을 만든다(기존 `InteractionContextType(pub u8)` 패턴을
`new(raw)`/`get()`과 비공개 저장으로 통일). 알 수 없는 값도 왕복 보존하고, 더 큰 정수를 `as u8`로
자르지 않는다. 감사 로그 액션처럼 넓은 값은 넓은 저장 타입을 쓴다. 프로토콜이 정하지 않은 기본값은
두지 않는다.

변환 대상(모델, 요청 본문, 쿼리, 이벤트 필드, 빌더 setter 동시): ChannelType, OverwriteType,
ComponentType, ButtonStyle, TextInputStyle, SeparatorSpacing, MessageType, MessageReferenceType,
MessageActivityType, InteractionType, InteractionResponseType, CommandType, CommandOptionType,
CommandPermissionType, VerificationLevel, DefaultMessageNotificationLevel,
ExplicitContentFilterLevel, MfaLevel, PremiumTier, GuildNsfwLevel, VideoQualityMode,
ForumSortOrder, ForumLayout, ScheduledEventStatus, ScheduledEventEntityType, 도메인별 privacy level,
AutoModerationEventType/TriggerType/ActionType, KeywordPresetType, AuditLogActionType, InviteType,
InviteTargetType, InviteTargetUsersJobStatusType, WebhookType, StickerType, StickerFormatType,
PollLayoutType, ReactionType, SkuType, SkuAccessType, EntitlementType, EntitlementOwnerType,
SubscriptionStatus, UserPremiumType, ConnectionVisibility, RoleConnectionMetadataType. 기존
`ApplicationIntegrationType`, `InteractionContextType`, `ApplicationCommandHandlerType`,
`ActivityType`, `WebhookPayloadType`는 유지.

문자열은 어휘(예: 프레즌스 status → 열린 문자열 newtype)와 임의 텍스트(파일명, 외부 ID, MIME,
URL, 메타데이터 → 그대로)를 구분한다.

`ChannelType`이 `is_thread()`, `is_voice_based()`, 텍스트 가능 분류를 소유한다(분류가 전송 권한을
뜻하지 않음을 문서화). `model_ext.rs`의 비공개 중복 상수를 제거한다.

시리즈 1 구현(`src/model/discriminant.rs`, 2026-10-11): 값은 discord-api-docs `3714862` 기준.
저장 폭은 모두 `u8`이고 `AuditLogActionType`만 `u16`(문서 최댓값 193)이다. 폭을 넘는 값은 디코딩
오류가 된다. 공개 API는 연관 상수, `new`/`get`, 알려진 상수 이름을 돌려주는 `name()`이다.
Discord가 이름을 주지 않은 값은 discord.rs가 이름을 붙였다(`OverwriteType::{ROLE, MEMBER}`,
`SeparatorSpacing::{SMALL, LARGE}`, `EntitlementOwnerType::{GUILD, USER}`). `SkuAccessType`은 값이
문서화되지 않아 상수가 없다. Discord가 deprecated로 표시한 값(`PREMIUM_REQUIRED`, stage
`PUBLIC`)은 문서에만 적고 `#[deprecated]`는 붙이지 않는다(옛 payload 디코딩에 경고가 생기므로).
이름이 2.x 타입과 겹치는 7개(`ChannelType`, `MessageReferenceType`, `ApplicationIntegrationType`,
`InteractionContextType`, `ApplicationCommandHandlerType`, `ActivityType`, `WebhookPayloadType`)는
`model::discriminant` 경로에만 두고 시리즈 3에서 교체한다. 위에서 "유지"한다고 한 5개도 이름은
유지하되 매크로 형태(비공개 저장, `Default` 없음)로 바뀐다.

권한은 `Permissions`로 통일하고 필요하면 `PermissionsBitField`를 deprecated 별칭으로 둔다. 모르는
비트는 보존하고 음수 입력은 거부한다. `bitfield.rs`의 직렬화는 현재 모든 비트필드를 문자열로
내보내는데, 권한은 문자열이 맞지만 메시지 플래그·인텐트는 숫자여야 하므로 타입별로 나눈다.

## 3. 생략·null·이벤트 소유권 (4단계)

```rust
pub enum Patch<T> { Missing, Value(T) }
pub enum Nullable<T> { Null, Value(T) }
pub type NullablePatch<T> = Patch<Nullable<T>>;
```

| 필드 예 | 타입 |
|---|---|
| 메시지 content 수정 | `Patch<String>` |
| 컴포넌트 교체 | `Patch<Vec<MessageComponent>>` |
| 멤버 닉네임 지우기 | `Patch<Nullable<String>>` |
| 음성에서 내보내기 | `Patch<Nullable<ChannelId>>` |
| bool 수정 | `Patch<bool>` (null 불가) |
| 필수지만 null 가능한 스냅샷 필드 | `Nullable<T>` |

serde 규칙(시리즈 1 구현 `src/model/patch.rs`, 2026-10-11 리뷰 반영):

| 필드 종류 | 선언 | 키 생략 | `null` | 값 |
|---|---|---|---|---|
| 패치 | `#[serde(default, skip_serializing_if = "Patch::is_missing")] f: Patch<T>` | `Missing` | `T`가 받으면 값, 아니면 오류 | `Value` |
| null 가능 패치 | 같은 속성, `NullablePatch<T>` | `Missing` | `Value(Null)` | `Value(Value(_))` |
| 필수 null 가능 | 속성 없음, `Nullable<T>` | **오류** | `Null` | `Value` |
| 위 패치에서 `default`를 빠뜨림 | | **오류**(지우기로 바뀌지 않음) | | |

- 생략 처리는 타입이 강제한다. `Patch`와 `Nullable`의 `Deserialize`는 `deserialize_newtype_struct`로
  들어간다. serde derive가 생략된 필드에 쓰는 `missing_field` 역직렬화기는 `deserialize_option`에만
  `visit_none`으로 답하고 나머지 요청에는 "missing field" 오류를 내므로, `Option<T>`와 달리
  생략이 null로 읽히는 경로가 없다. 실제 역직렬화기는 `visit_newtype_struct`로 자신을 돌려준다.
- 그래서 필드마다 `deserialize_with`를 강제하는 관례나 검사 매크로는 두지 않는다. 속성을
  빠뜨려도 조용히 틀리지 않고 오류가 난다. `default`를 빠뜨리면 생략이 오류가 되고,
  `skip_serializing_if`를 빠뜨리면 `Missing` 직렬화가 오류가 된다.
- 지원 형식은 JSON(serde_json의 텍스트·리더·`Value`·`&Value`, untagged·내부 태그·flatten 컨테이너)
  이다. newtype을 `deserialize_any`로 넘기는 역직렬화기(serde `value` 모듈)용 `visit_*` 폴백은
  data model의 모든 형태(128비트 정수, enum 포함)를 넘긴다. 다른 형식은 목표가 아니다. 쓰기는
  `serialize_none`/값 그대로, 읽기는 `Option<T>`와 newtype 진입이라 option·newtype 인코딩이 JSON과
  다른 형식에서는 쓴 것을 그대로 읽지 못할 수 있다. serde가 `missing_field` 동작을 바꾸면 생략
  테스트가 실패해 알려 준다.
- `Default`는 `Missing`(`T: Default` 불요). `Nullable`에는 `Default`가 없어 필수 필드에 실수로
  `#[serde(default)]`를 붙이면 컴파일 오류가 난다. 단독 `Missing` 직렬화는 오류(조용히 null로
  바꾸지 않음). 태그 없는 표현.

현재의 `Option<Option<T>>` 요청 필드를 엔드포인트별 실제 null 허용 여부를 확인한 뒤 바꾼다.

부분 갱신 이벤트 DTO: `MessageUpdate`, `GuildUpdate`, `MemberUpdate`, `PresenceUserUpdate` 등
(이름이 `_UPDATE`라고 모두 부분 갱신은 아님). `MessageUpdate`는 변경 가능한 모든 수신 필드를
표현한다(Missing = 유지, null = 지움, 빈 배열 = 빈 값으로 교체). 갱신만으로 가짜 전체 메시지를
만들지 않는다. 외부 캐시 백엔드에는 패치 인식 연산이나 병합된 권위 스냅샷을 보낸다(W1의 순서·샤드
규칙 유지).

### 이벤트 API

`Event`를 봉투로, 기존 payload enum을 `EventKind`로 바꾼다.

```rust
pub struct Event { /* kind: EventKind, metadata: EventMetadata, raw: Option<Box<RawValue>> */ }
pub enum EventKind { MessageCreate(..), MessageUpdate(MessageUpdate), /* ... */ Unknown, DecodeFailed(EventDecodeError) }
pub fn kind(&self) -> &EventKind;
pub fn metadata(&self) -> &EventMetadata; // dispatch name, shard, sequence, receive time
pub fn raw(&self) -> Option<&RawValue>;
async fn handle_event(&self, ctx: Context, event: Arc<Event>);
```

- raw는 한 곳에만: 알려진 이벤트는 `keep_raw_events(true)`일 때만, 알 수 없는 디스패치와 디코드
  실패는 항상 보관. 생성자가 이 불변식을 강제하고, 커스텀 `Debug`는 raw 내용을 출력하지 않는다
  (W2의 토큰 가리기 유지). 알 수 없는 이벤트와 깨진 알려진 이벤트를 구분한다.
- `serde_json/raw_value`를 켜고 `op`/`s`/`t`와 빌린 `&RawValue` `d`만 담은 얕은 봉투를 파싱한다.
- 게이트웨이 읽기 루프는 분리 유지: 소유한 raw 디스패치를 W1의 bounded 내부 처리기로 넘기고 거기서
  디코딩한다(큰 GUILD_CREATE를 하트비트 읽기 루프에서 동기 디코딩하지 않는다).
- 파이프라인: frame → 얕은 봉투 → bounded 디스패치 큐 → 타입 디코딩 → 순서 보장 내부 갱신 →
  `Arc<Event>` → 핸들러/컬렉터. Value 트리, 타입+raw 깊은 복제, 캐시 병합 중 raw 파싱 없음.
- 컬렉터는 `Arc<Event>`를 broadcast하고 참조로 필터링, 일치한 payload만 복제해 기존 `next()` 유지,
  공유 접근용 `next_event() -> Option<Arc<Event>>` 추가. 메시지 생성/수정 수집을 구분한다.

## 4. 요청 모델·빌더·REST 이름 (5단계)

`src/request.rs` 퍼사드 아래
`request/{message,component,modal,embed,command,guild,channel,member,role,webhook,interaction,moderation,scheduled_event,media,component_embed}.rs`.
응답 도메인 타입은 `model`에 남긴다.

| 요청 타입 | 용도 |
|---|---|
| `CreateMessage` | 채널 메시지 생성(reference, sticker, nonce, poll, content/components/embeds) |
| `EditMessage` | 패치 의미, nonce·sticker·reply 없음 |
| `InteractionMessage` | 초기 콜백 메시지(ephemeral, poll 포함) |
| `EditInteractionResponse` | 원본 응답 수정 |
| `CreateFollowup` | 후속 메시지 |
| `ExecuteWebhook` / `EditWebhookMessage` | 웹훅 실행/수정(첨부 유지 명시) |
| `InteractionResponse` | REST와 HTTP 엔드포인트가 공유하는 타입 콜백 enum (+ raw 탈출구) |

손실 있는 `From<CreateMessage> for InteractionReplyData`는 제거(무손실 또는 명시적 실패 변환만).
첨부 메타데이터는 기존 `AttachmentId`와 새 `UploadId`를 구분하는 enum.

빌더는 중간 JSON 없이 요청 모델을 들고 있다. `build()`는 한도 미검사, `try_build()`는 검사 후 같은
타입 반환. 나가는 컴포넌트는 데이터 enum(버튼: custom/link/premium 분리, 행: 버튼 행/단일 선택 행,
모달 label 자식, section accessory: 버튼/썸네일, 눈에 띄는 `Raw` 탈출구). 알려진 숫자 태그는 숫자로
직렬화한다(문자열 태그 serde enum에 의존하지 않음).

Component Embed 생성: `ComponentEmbed { component: PreviewContainer }`와 제한된 `PreviewComponent`
계열. 링크 버튼만 허용, 중첩 컨테이너·raw 금지, 일반 컨테이너에서의 변환은 실패 가능. 직렬화 크기,
갤러리 합계, 컴포넌트 수, 미디어 URL 검사. JSON과 `<script>` 출력 제공, `<`를 이스케이프하고 실제로
이스케이프된 JSON 길이로 3,000바이트를 잰다. 수신용 `Embed.components`(1.5단계)와 분리한다.

REST 이름: `_typed` 쌍 41개와 단독 `_typed` 5개를 정리한다. 정규 엔드포인트는 구체 요청 DTO를
받는다. `modify_guild` 유지(`update_guild*` 제거), `create_guild_role`/`modify_guild_role` 유지
(`create_role*`/`update_role*` 제거), `update_channel`은 `ModifyChannel`을 받음, `_with_query`/
`_with_files` 유지, `_from_request`/`_with_body`/`_config` 별칭은 정규 메서드로 합침,
`get_public_archived_threads` 제거. 일반 엔드포인트는 제약 없는 `B: Serialize`를 받지 않는다
(Slack/GitHub 호환 웹훅 본문, 애플리케이션 정의 메타데이터는 문서화된 예외). raw 탈출구:

```rust
pub async fn request<T: DeserializeOwned>(&self, request: RawRequest<'_>) -> Result<T, DiscordError>;
```

1단계의 `RequestRoute`를 확장해 실행과 W7의 drift 리포트가 같은 출처를 쓴다.

## 5. 실행 순서와 소유권

먼저 `model.rs`를 도메인 파일로 기계적으로 나누고(guild/member/role/guild_aux, message/component/
embed/poll/interaction, command/application, invite/webhook, moderation/audit_log/scheduled_event/
media/monetization/lobby/presence/voice, 공통 트레이트는 `model/entity.rs`), `http.rs`의 엔드포인트
구현도 도메인 모듈로 옮긴다. 이 커밋에서는 이름 변경, Default 제거, serde 속성 변경을 하지 않는다.

| 시리즈 | 작업 | 규모 |
|---|---|---|
| 0 | 워커 병합, 기준선 고정, model/REST 기계적 분리 | M |
| 1 | ID·판별값·Patch 기본 타입과 계약 테스트 추가(기존 사용처 미변경) | M |
| 2 | ID, Default, 다형 대상, 매니저·캐시 키, 권한 이전 | L |
| 3 | 판별값 필드와 사용처 이전, 중복 상수 제거 | M |
| 4 | 부분 갱신 DTO, 패치 인식 캐시·백엔드 | L |
| 5 | 게이트웨이 디코딩, 이벤트 봉투, 핸들러·컬렉터 공유 전달 | L |
| 6 | 타입 요청·컴포넌트 모델, 빌더·엔드포인트·응답기 이전 | L |
| 7 | 과도기 어댑터·별칭 제거, 문서·마이그레이션 마무리 | M |

병렬 규칙: 조정자 한 명이 `lib.rs`, `prelude.rs`, 퍼사드, Cargo, 공유 트레이트, 계약 변경을
소유한다. 도메인 작업자는 자기 도메인의 model/request/HTTP 파일을 함께 소유한다. 런타임 작업자 한
명이 event*/gateway*/cache*/manager.rs/컬렉터 통합을 소유한다. 응답 작업자 한 명이 response.rs/
interactions.rs/helpers.rs/콜백 요청 통합을 소유한다. 시리즈마다 작업자 파일 목록을 고정한다.
ID 이전처럼 서로 얽힌 변경은 일회용 통합 브랜치에서 모아 녹색 체크포인트로 병합한다. 중간 브랜치를
컴파일시키려고 일반 ID 변환으로 시그니처를 약하게 만들지 않는다.

필수 테스트: trybuild compile-fail(채널 ID를 길드 엔드포인트에, 암시적 마커·u64 변환, 저장 모델
Default, 비-null 패치에 null, 미리보기 행의 custom-ID 버튼, edit에 create 전용 필드, 응답기 Send
계약), 왕복 테스트(ID 거부·정규화·맵 키·8바이트 크기, 위젯/설치 주체 "0", 커맨드 권한 센티널,
알 수 없는 판별값·권한 비트 보존, Missing/Null/Value와 false·0·빈 문자열·빈 배열, 부분 갱신이 생략
필드를 덮지 않음, 공유 이벤트 전달과 미일치 컬렉터 무복제, raw 보관 규칙과 Debug 비노출, Component
Embed 이스케이프 후 한도, 감사된 모든 경로의 method/path/query/auth/body 골든 픽스처).

compile-fail 케이스는 `tests/ui/*.rs`에 추가한다. `tests/compile_fail.rs`는 `DISCORDRS_TRYBUILD=1`일
때만 돌고, CI는 고정 툴체인 작업(`rust-check`의 "Compile-fail snapshots")에서만 켠다. 스냅샷 갱신
절차는 `discordrsdocs/docs/guide/testing-and-coverage.md`에 있다. 생략 처리 테스트(필수 `Nullable`
생략은 오류, `default` 없는 패치 생략은 오류, `default` 있는 패치 생략은 `Missing`)는
`src/model/patch.rs`에 있다.

## 6. 3.0에서 하지 않는 것

크레이트 분할, OpenAPI 생성 모델·클라이언트, 모든 빌더 한도의 typestate, 측정 없는 새 동시성 캐시,
컬렉터용 범용 소유 투영 기계, 외부 ID·로컬 인덱스·임의 문자열용 마커 타입, 정당한 `Value` 필드
(애플리케이션 메타데이터, 알 수 없는 payload, 이질적인 감사 값) 제거, 미관만을 위한 REST 동사 변경.

가장 중요한 순서 제약: **raw에 의존하는 캐시 로직을 없애기 전에 패치 의미를 먼저**. 가장 중요한 ID
제약: **유효한 0/센티널 와이어 값은 전용 표현으로**.
